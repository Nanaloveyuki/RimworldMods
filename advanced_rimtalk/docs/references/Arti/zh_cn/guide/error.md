# error

Arti 会把错误保留在提示词结果中，并附带诊断码和位置：

```text
[Advanced RimTalk Arti error ART2008 at 3:5: ...]
```

运行时错误可能使用：

```text
[Advanced RimTalk Arti error: ...]
```

## 错误阶段

### 解析错误

代码无法按 Arti 语法读取，例如：

- 字符串没有闭合；
- 括号或花括号不匹配；
- 使用了不支持的块注释；
- 正式代码块没有 `%}}`。

### 分析错误

代码结构可以读取，但名称或控制流不合法，例如：

- 未知变量或模块；
- 必需模块缺失或未启用；
- 给 `const` 重新赋值；
- 在函数外使用 `return`；
- 在循环外使用 `break`；
- 函数参数数量或名称不匹配。

### 运行时错误

代码已经通过分析，但执行时失败，例如除数为零、随机范围无效、调用深度超限或步数超限。

## 诊断码

错误标记中的诊断码可以帮助你快速判断阶段：

| 范围 | 阶段 |
| --- | --- |
| `ART1000`–`ART1008` | 词法错误 |
| `ART2001`–`ART2020` | 解析错误 |
| `ART3000`–`ART3015` | 分析错误 |
| `ART4000` | 运行时错误 |

## 排查顺序

1. 读取错误标记中的代码和行列位置。
2. 确认代码位于 `{{% ... %}}` 中；普通 Scriban 和 Markdown 代码围栏按各自的流程处理。
3. 检查可能为空的 `pawn`、`recipient`、`map` 和查询结果。
4. 检查模块是否使用了 [`optional`](../language/optional.md) 或是否真的已启用。
5. 暂时用 `core.log` 或 `core.diag.warn` 输出开发诊断。
6. 把复杂代码拆成多个局部变量和小函数，再逐步恢复。

如果日志中没有错误但结果不对，先确认当前使用的是嵌入模式还是接管模式；两种模式执行的文档不同。
