# Oxygen 后续需求解析

## 1. 目标与本轮范围

动态心情 MVP 已完成，并已验证脚本修改、效果更新、错误保留有效版本、清理和存档恢复这条闭环。后续不再围绕“是否可行”重复验证，而是扩展真实 Mod 创作能力。

产品方向：**逐步代替传统 XML Mod 的内容声明与修改方式，并承载常见玩法规则**。作者可以用 Oxygen 定义、组合、引用和修改原生游戏内容，不必为同一功能另外手写 Def XML、Patch XML 和零散 C# 接线。

需求解析阶段已结束，第一批已实现并做集中构建、离线消费端和隔离游戏验收。后续条目仍是目标，不表示本批覆盖；不建立大型测试设施，也不追求全游戏／第三方组合完备。实际接口见 [语法文档](syntax-draft.md#原生内容与运行规则)，已运行证据见 [验证记录](validation.md)。

本页是后续方向，不改写已有 MVP 的验收历史。当前实现记录见 [mvp.md](mvp.md)、[syntax-draft.md](syntax-draft.md) 与 [validation.md](validation.md)。

## 2. 边界改为阶段状态

必须分开两个问题：**是否能用 Oxygen 表达一个 Mod**，以及**这项变更是否能在已有存档里立即热更新**。需要重新加载的定义仍然属于 Oxygen 的内容能力，不能因为尚未支持热迁移就要求作者永久退回 XML。

| 项目 | 当前状态 | 后续方向 |
| --- | --- | --- |
| 语言与模块 | 已有动态绑定、后置约束、struct、组合、模块 | 复用现有语言，不先重做解析器或引入另一套 DSL |
| 心情 | 已有动态效果／记忆及原生多阶段 ThoughtDef 规则 | 事件记忆与更多原生宿主 |
| 内容定义 | 已有 TraitDef／ThoughtDef 声明、引用、模板／Def继承／组合、常用字段修改 | 扩大 Def 覆盖与实例迁移 |
| Pawn | 已有特质、身份、需求类别、疾病及群体查询，RHAH 三态闸门 | 动作预制件、生成配置、行为组合 |
| Job/WorkGiver/健康/基因等 | 当前没有 DSL 宿主支持 | 分批纳入，不列为产品永久禁区 |
| 类型和补丁扩展 | 当前不允许任意 C#、反射或 Harmony 操作 | 提供注册的原生类型、Comp/Worker/Driver 和扩展接点；脚本不必自己维护裸补丁生命周期 |
| 游戏集成 | 已有 Mod 自动 content／rules 入口、归属与独立停用 | 更广依赖、兼容与发布流程 |
| 热更新 | 心情和规则可热重载；本批原生内容修改要求重启 | 原生字段定向刷新与实例迁移 |
| 包装与发布 | 仍用现有 RimWorld Mod 包装 | 先替代 Def/Patch 内容；About、版本/DLC目录与 LoadFolders 的作者声明/生成列入后续工作 |

C# 仍负责与游戏引擎接合，不等于“作者必须继续写这些 C#”。未来可由框架的预制件和声明式组合承载更多行为。任意方法执行、万能回滚、完整 CLR 类型生成不是下一批实现前提。

## 3. 功能需求

### R1. 原生内容声明与引用

- 可以创建真正的 TraitDef、ThoughtDef，而不只是给共享载体加脚本标签。之后按批次扩展 HediffDef、GeneDef、XenotypeDef、ThingDef、RecipeDef、PawnKindDef、IncidentDef、Job/ThinkTree 等。
- 内容身份使用稳定 ID/defName，记录提供者 packageId。能引用 Core、DLC、其它 Mod 的 Def；兼容缺少可选依赖的声明。原生类型引用、带 Def 类型的引用、模板/继承目标分开；defName 不自动等同于 XML 抽象父节点名。
- 模板支持抽象内容、继承已有定义与组合预制件。它与语言 struct 的引用语义分开：展开子内容不能意外共享可变字段，使修改一项污染其它 Def。
- 原生字段不能因为首批没有便利封装就永远不可表达。第一批建立已覆盖 Def 类型的字段映射，并给 C# 扩展注册新映射/类型的入口；未知字段报错，不默默丢弃。
- 原生类型引用必须解析到实际程序集类型，并检查要求的基类，例如 thingClass/workerClass/compClass。不是“字符串被接受即有效”。
- 声明解析形成可检查的内容计划，再交给原生加载/引用解析流程；不先自研另一套游戏 DefDatabase。内容声明、运行规则注册与 Pawn 条件求值分开，允许宿主按已实现的能力扩展，不继续把全部游戏功能写死成 mood/memory 两个名字。
- 内容注册应接入游戏加载与引用解析的正确阶段，在消费方建立缓存之前完成；首次定义不以进入地图后点击应用作为唯一入口。
- 已有 RHAH defName 与显示 ID 在迁移时保持原身份；框架命名空间不能替作者悄悄改名。

第一批验收意义：**作者能不写 Def XML，声明一个有真实数值效果的特质、它的思想和条件，并被原生游戏系统识别。** 不能只完成一个看起来像特质的脚本状态。

### R2. 修改已有内容，替代 Patch XML

- 能对已加载内容执行明确的字段设置、列表追加/移除和已有项修改；支持 Mod/DLC 存在条件。
- 定义应用顺序、目标缺失、匹配零项/多项以及覆盖冲突的处理。报错包含脚本位置、提供者、目标和字段。
- 第一批只实现上述常用修改，不要求完整 XPath 引擎或所有第三方 PatchOperation 的复制。
- 提供本框架修改前后值、已知来源和应用顺序，足够定位本框架覆盖关系；不能据此声称能追踪所有外部 C#/Patch 修改者。先不建设完整补丁溯源数据库、依赖图和可视化编辑器。
- 可与传统 XML Def/Patch 共存。加载先后必须明确，不能假设 Oxygen 总是最后执行。
- 引用与动作遵守最终加载后的 Def 及实际许可，不把提供者原始 XML 当最终状态。需要来源限制时能同时检查 defName 和 packageId；定义来源不表示内容从未被第三方修改。

第一批验收意义：能用一项 Oxygen 修改替代真实 Patch XML 操作，且缺少目标时不产生半份定义或假成功。

### R3. 特质、思想、属性与条件

- TraitDef 支持等级、数值、互斥与生成关联；ThoughtDef 支持阶段、所需特质、持续时间和叠加方式。
- Pawn 查询至少包括特质/等级、当前身份/派系、发育阶段、需求类别、疾病/倒地与必要的群体事实。游戏枚举类别不能简单替换成任意百分比分段。
- 情境规则可返回未激活或一个明确阶段，有多个条件时声明优先级。
- 连续条件、事件触发和概率抽取分开。立即检查连续条件不能重复生成一次性事件效果。
- 数值契约区分原生基值、附加偏移、倍率与最终合成效果，避免 XML 基值与脚本附加值意外重复计算。
- 固定数值特质不必迁移成逐 Pawn 周期脚本；原生计算能处理的声明仍走原生路径。
- 特质授予区分普通来源与基因来源，遵守原生读档清理；重应用声明不覆盖 Pawn 的全部特质，不抹掉玩家或编辑器添加的条目，也不无证据地在读档时强制补回。
- 特质等级/思想阶段与标签、描述、翻译路径绑定，使用原生真实嵌套字段。描述引用实际配置，不承诺尚未接线的行为；首批不做自动文案生成或完整语言工具链。

RHAH 第一组样例：吃苦耐劳的属性定义；喜爱幼儿及其饥饿/病倒阶段；害怕生病的自身/群体两种思想。保留现有 Lord/自由殖民者群体语义；“半径内”“只看亲生孩子”属于另行声明的新规则。

### R4. Pawn 策略与动作预制件

- 规则表达“什么时候、对谁、允许/拒绝/不参与、选择什么已有动作”。后续可扩展评分和行为组合，不把策略层当永久能力上限。
- 动作由框架接入 Job/Toil/WorkGiver 等机制。脚本作者不必自行拼预留、赶路、执行、中止与通知。
- 明确适用对象：来源标记、当前角色、当前派系和生命周期不是同一个维度。不同作用域不能只用一个 visitor 布尔值混代。
- 查询/预览无副作用；执行时重新检查目标、权限和实际持有/地图等条件。展示时允许不代表执行时一定允许。
- 动作结果区分已接受/排队、已开始、已完成与失败，附可读原因。入队或写登记不能自动计作交付、加入或生成成功。
- 每个预制件明确成功条件和已有 Job 如何衔接。不是统一“总中断旧 Job”，也不是“只改 duty，任旧任务继续”。
- 失败后的再发必须尊重该动作原生冷却/资格与调度时机，避免同一 tick 重开循环；不把无限重试当通用功能。
- 行为查询明确对象范围与触发/评估时机，复用宿主集合；先筛选少量候选再寻路，启动时实际预留。先不做复杂全局调度器，但不能默认每 Pawn 每 tick 全图扫描。
- 主线程执行还需满足原生生命周期阶段，例如地图初始化完成后才能执行依赖地图的动作或清理；同步调用不能冒充生成完成回调。

RHAH 先通过稳定 Api.dll 适配已有闸门。三态策略沿用 Pawn 覆盖 → 行为策略 → 默认规则的现有顺序；一个稳定适配器读取当前规则快照，不反复注册，也不把条件输出周期写成永久 SetGate。

### R5. 生成、事件与选择

- 内容目录能声明经历/特质关联、年龄与温度条件、权重、事件角色/家庭配方。现有年龄、显式配置和选择优先级不能在迁移时悄改。
- 随机来源由宿主提供，离线可给固定输入；不要在一个纯判定里反复隐式重抽。
- 生成完成后核对实际种族、异种/基因和所要求的状态；请求被提交不等于已安装。显式指定不可用时失败，不偷偷换成其它对象。
- 失败清理限于本次创建/登记的内容，不要求通用世界回滚。
- 事件事实在动作确认后发布；一次性授予、计数和奖励沿用稳定事件/对象身份，读档与重应用不能重放。
- 选择选项在点击时重查资格。失败保留上下文；成功只关闭所属窗口/结算对应事件，不按窗口类型一锅关闭。
- 批次按成员记进度、截止和结果；“有人完成”“全部完成”“至少成功一人”分别声明。空集合是否完成必须明确。
- 延迟执行保存原始目标的稳定引用，区分暂不可用与永久失效，不偷偷重新随机目标；终止失败不留在队列无限重试，等待项不阻塞无依赖的可执行项。

先接短事件，例如实际接济后的结果；长剧情链和结局规则之后再做。它们仍在目标内，只是持久阶段和奖励语义成本更高。

### R6. Mod 入口、状态与归属

- 区分内容声明入口、运行时规则入口和可导入库。use 不应意外启用另一 Mod 的玩法，也不能只靠玩家给每个存档手动粘贴主脚本。
- 支持多 Mod 内容/规则隔离、依赖、稳定归属、独立停用和错误定位，复用现有 Oxygen/ 模块路径。
- 持久状态显式声明；普通 let/模块变量仍是临时执行状态。不把整个解释器对象图、闭包和任意宿主对象直接存档。
- 保存稳定 Def/规则身份和必要状态版本；游戏对象通过可解析稳定引用恢复，不能把瞬时对象句柄当永久身份。
- 重载时说明“保存版本/当前依赖版本不一致”的处理。最低要求是不静默重演效果、不以新阶段含义误读旧状态；首批保持状态格式或拒绝不兼容升级即可，不预建万能迁移系统。
- 内容下架、运行规则停用、撤销可撤销效果和导出卸载是不同操作。特质授予、伤害、出生、已交付物资不能承诺一键无损回滚。
- 记录持久产物和清理方式。完整卸载导出属于后续能力；首批至少能报告仍被引用、不可删除或不可安全停用的内容，不自动删除有关 Pawn/地图。
- 期限使用模拟时间，必要的倒地等暂停条件单独声明，显示读取同一权威状态。关闭新内容入口不解除已有实例的超时与清理责任；语义终态也不等于所有资源已经释放。

### R7. 热更新生效方式

所有变更明确归入一个生效方式，而不是只有成功/失败：

| 类别 | 首批策略 | 后续可以扩展什么 |
| --- | --- | --- |
| 条件、心情强度和可重评估参数 | 原子切换规则/配置，按宿主需要失效缓存或重评估 | 更广的原生字段和定向刷新 |
| 生成权重、配方和未来事件规则 | 影响未来生成/下一次判定，不自动重造现有 Pawn | 显式重应用与迁移操作 |
| 新增 Def、Comp/Worker/阶段结构等 | 支持 Oxygen 声明与启动加载；现阶段可要求重启，保留待应用编辑 | 正确注册、缓存更新和已有实例重绑定 |
| 已运行 Job、事件阶段、已提交效果 | 沿用当前动作/已保存语义，不重新执行 | 有明确转换规则的迁移 |

运行中替换前的语法、字段、引用与候选注册验证失败时保留上一有效版本；首次启动没有旧版本时明确拒绝无效内容并报告原因，不承诺恢复不存在的旧状态。这个承诺针对替换前可验证的定义/规则，不等同于所有真实动作都能回滚。

原版有 Def 热重载，但它不是本框架的完整契约。框架必须报告本次修改实际属于哪一类，不能以“解析成功”冒充“已有实例已迁移”。

### R8. 低成本开发反馈

- 无游戏的解析/字段/引用检查和规则试算，共用真实声明与规则处理路径。
- 试算给 Pawn/事件事实和固定随机值，输出命中条件、阶段、修改值或动作计划；不假装执行寻路/预留/健康副作用。
- 使用从活动模组取得的类型/Def 目录时记录版本；目录不完整或第三方动态内容无法判断时标未知，不宣称游戏一定可加载。
- 运行检查沿用现有窗口，新增内容来源、实际生效方式和最短失败原因。先不做通用追踪系统、可视化流程编辑器或全游戏确定性重放。
- 自动化情景包在功能集成末尾使用；本轮不建设，也不拿已完成 MVP 重新反复证明可行性。

## 5. 实施批次

### 第一批：真正跨出心情工具，完成最小 XML 内容替代

1. 复用现有语法，加入内容声明与注册接点、稳定 ID/引用及原生类型字段映射。
2. 接 Mod 自动内容入口和规则入口，形成多 Mod 归属，不依赖单份玩家主脚本。
3. 新建 TraitDef/ThoughtDef，支持模板/组合、常用字段与一项真实已有 Def 修改。
4. 接 Pawn 特质/身份/需求查询、多阶段思想规则和 RHAH 已有闸门适配。
5. 提供最小离线检查与无副作用试算；保留错误时上一有效定义/规则及明确生效方式。

本批交付样例：一个无 Def/Patch XML 的特质＋思想内容包；新建内容、组合和已有内容修改均走同一管线；一个 RHAH 三态行为策略。结构变更要求重启属于当前生效方式，不使这批退化成“仍必须用 XML 定义”。

本批已交付：`Examples/NativeTraits`、`Examples/RhahPolicy`、离线 `Oxygendsl.Tool`、自动内容宿主和可选 RHAH 适配程序集。游戏实测确认原生工作速度倍率、多阶段思想、所需特质条件、规则错误保留、存读档停用归属及实际 RHAH 权限优先级。未把 RHAH 现有内容整体迁移，也未新增动作 DSL。

不在本批塞完整生成器、完整任务 DSL、所有 Def schema、全部 XML XPath、剧情图编辑器或完整卸载导出。

### 第二批：把已存在的游戏动作变成作者能力

扩展内容目录/生成配方、有限事件事实和动作预制件、接济后的结果与选择。优先接实际可复用的原生流程，不为每条玩法规则生成 Harmony 补丁。

当前事件链接入沿此方向实现：ODF 持有 provider 分区、版本化实例、到期队列与动作回执；RHAH 保留已有游戏动作、Pawn／捕食 AI 和 NarrativeState。旧链与地图侧到达延迟在激活前迁移，成功后只写 ODF 格式，不保留双引擎。`events.ctx@event` 在事件宿主返回受限决议，不是通用 Job DSL。本批不新增物品、心情、事件或剧情。

### 后续批次：扩大传统 XML 替代覆盖

Hediff/基因/异种、物品/建筑/配方、PawnKind/事件与任务、Job/WorkGiver/ThinkTree 的声明与组合，更多字段修改、实例重绑定/迁移和发布包装。依赖对应原生宿主接点，不再列作永远“应该留 XML/C#”的功能。
