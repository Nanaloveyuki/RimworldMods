# 卸载导出

本页说明停用新内容和安全导出卸载副本的玩家流程。导出不是无损停用；请保留备份，确认副本可继续游玩后再处理旧档。

## 玩家流程

先保留本模组及其前置，加载要处理的存档。原版模组设置页和 IrisMenus「存档与卸载」页提供以下操作；未加载存档时不可用，不需要安装 IrisMenus 才能导出。

1. **只想暂停新内容：选择「仅此存档停用新内容」。** 它只影响当前存档，不改变全局开关；停止本模组的事件后续和待到达内容，保留已有来客、信件和世界物体。自行再保存一次，停用状态才会写进存档。这一步本身不表示可以卸载模组。
2. **准备卸载：选择「备份并导出卸载用副本」。** 游戏暂停，先把点击时的当前状态保存为独立的 `RHAH-backup-*` 备份，再在内存中停用新内容并清理序列化副本。备份保留点击导出前的停用状态；成功后生成 `RHAH-removed-*`。**原档不覆盖，正在运行的世界不清理，并保持暂停。**
3. **收到成功提示后退出游戏，再卸载。** 只卸《鼠族：饥与祸》（RHAH），保留鼠族、Harmony、Biotech、Oxygen DSL Framework（ODF）及其它前置。重启后加载提示中的 `RHAH-removed-*` 副本，不要选原档或备份。确认副本能加载、运行、保存、再加载，再决定是否删除旧档。
4. **保留备份以便恢复。** `RHAH-backup-*` 仍含本模组数据，加载它或原档时必须保留本模组。导出失败时，不卸载本模组，不把备份或临时文件当成清理副本。


## 明确不做

- 不扫描、不转换旧鼠灾存档
- 不删其它模组的特质、种族、基因、Hediff
- 不改全局 `ModSettings`。卸模组后设置文件可以残留
- 不猜测删除未知的本模组 Def 或类型。遇到 `RHAH_` 标量、`HungerAndHavoc.` 类型或已删除对象的残留引用就中止
- 半成品不改名为可卸载副本

## 导出影响与风险

清理只针对 RHAH 自有内容。本模组专属状态和内容会被移除，部分保留对象需要改用已加载的原版或前置内容；例如经历替换可能影响技能，穗音会改为原版故事讲述者。因此副本不应当作原档的等价备份，也不保证与所有第三方模组组合兼容。

清理会保留角色身份 ID、鼠族种族以及需要保留的已生成地点地图和居民；无法安全替换时中止，不通过改成人类或删除地图来完成导出。附着在本模组自有数据上的外部扩展数据可能一并丢失。

王国站点尚存的粮食会转入接收者背包的 `inventory/innerContainer/innerList`，保留每个堆的物品身份和数量，再移除站点；不把物品写在容器外层。

ODF 仍需保留。副本中只移除 RHAH 自己的事件分区，保留框架根数据和其它模组分区；不会清理正在运行的 ODF 状态。

所有权和卸载动作以 [save-ownership.md](save-ownership.md) 为唯一登记依据；实际行为见 [导出源文件](../Source/Core/RHAH_SaveExport.cs) 和 [清理源文件](../Source/Core/RHAH_SaveCleanup.cs)，本页不重复维护对象或代码符号清单。

## 文件与失败

- 备份名 `RHAH-backup-*`，副本名 `RHAH-removed-*`。已存在同名时换新名字，不覆盖玩家存档，也不覆盖上一次导出
- 清理副本先写入临时路径。写完并完成清理后才变成 `.rws`
- 未知的 `RHAH_` 标量、`HungerAndHavoc.` 类型、或已删除对象的残留引用：中止，记下路径和名字。未知本模组类型在任何删除或替换前检查
- 失败时设置和日志给出原因。不要把备份或半截临时文件当成清理副本
- 导出不覆盖原档、不清理运行中的世界、不改全局设置。若失败前已在内存中停用新内容，该停用状态仍保留；只有玩家自行保存后才会写进原档
