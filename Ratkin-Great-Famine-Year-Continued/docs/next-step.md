# 下一阶段事件路线

本文档记录 Continued 版本接手后的事件扩展方向。当前目标是先补足事件链和状态系统，再制作视觉资源。

## 当前基线

### 穗音信任度与威胁节奏

- 描述注明节奏接近兰迪，叠加鼠灾事件后整体难度更高。
- 启用 Mod 与剧情、选择穗音时，基地 RandomMain 的大型威胁权重乘以 `1 - clamp(trust, -100, 100) / 400`；久未触发大型威胁的 13 天阈值除以同一系数。
- 信任 -100 / 0 / 100 对应权重系数 1.25 / 1 / 0.75，补发阈值 10.4 / 13 / 17.33 天。阈值后仍等待主事件判定，权重系数不等于实际袭击次数比例。
- 包括袭击及其他大型威胁；保留单次点数、类别重试、空间限制与信标跳过逻辑。其他叙事者、任务袭击、商队和独立鼠灾触发不受此调整影响。
- 已随前次修复部署；实际节奏和存档切换仍需游戏内测试。

## 21 个候选方向

这些方向不是要求一次性全部做成随机事件。其中一部分应实现为已有事件的后续状态，否则只会增加 Def 数量而不会增加足够的玩法差异。

### 穗音与隐藏奖励

1. **穗音·开场**：首次鼠灾事件后发送专属叙事信，建立后续章节状态。
2. **灾荒记录册**：记录接济、情报、婴儿、鼠疫和威胁事件的完成情况，达到节点后推进章节。
3. **幸存者回礼**：完成若干不同类型的事件后发放一次不可重复的隐藏奖励。
4. **失落的鼠灾遗物**：通过隐藏线索生成一个世界地图地点，奖励独特物品、基因或特殊 Pawn。

### 婴儿囚犯

5. **囚笼转运队**：成人护卫带着婴儿囚犯抵达殖民地，提供交易、接收、驱逐或冲突分支。
6. **婴儿索取**：将当前一次性“难民接济（婴儿）”扩展为访客请求、替代资源、超时和拒绝分支。
7. **囚笼失窃**：鼠族尝试从监狱带走指定婴儿囚犯，玩家可以拦截或追击。
8. **逃出的鼠蛋**：婴儿囚犯脱离监狱后由成人带领逃离地图，形成限时回收事件。
9. **临时育婴营**：一批婴儿囚犯带有食物和医疗倒计时，处理方式影响事件结算。
10. **交换商人回访**：根据 `ChildExchange` 的成交、拒绝或超时结果触发后续事件。

### 灾荒与地图环境

11. **粮仓鼠洞**：指定食物储存区出现持续偷窃入口，随时间产生新的鼠族活动。
12. **粮食污染**：部分食物失效并增加鼠疫或清理压力，提供处理和放弃分支。
13. **农田抢收**：鼠群抢收成熟作物，玩家可以驱赶、投喂或围捕。
14. **啃墙逃生**：大灾荒鼠群破坏墙体和门，形成逃生路线或转为进攻。
15. **灾荒巢穴**：世界地图出现饥荒鼠族聚落，可援助、袭击或建立关系。

### 派系与访客

16. **内部争粮**：两批鼠灾流民因资源冲突分裂，玩家决定介入哪一方。
17. **幸存者使者**：隐藏派系派出代表，根据历史援助记录改变后续事件池。
18. **难民营迁徙**：玩家决定接收、护送或驱逐一个正在迁徙的鼠灾聚落。

### 鼠疫

19. **检疫封锁**：感染来客暂时不能加入、雇佣或转移，直到隔离或处理完成。
20. **病鼠带粮**：感染群携带食物或药品，处理方式在资源收益和传播风险之间取舍。
21. **康复者回访**：曾经存活的感染来客痊愈后返回，带来情报、交易或隐藏奖励。

## 第一批实现范围

第一批代码完成后，穗音头像和观音土贴图按单独需求使用 `gpt-image2` 生成并接入；其他视觉素材仍按后续需求处理。

第一批代码优先实现以下能力：

1. 新增可存档的叙事状态组件，记录当前章节、已触发事件类型、已完成里程碑和奖励是否领取。
2. 新增“穗音”叙事入口，优先使用信件和现有事件结果，不先实现完整替代原版 Storyteller 的复杂系统。
3. 新增一个一次性隐藏奖励结算点，奖励内容先使用已有 Def 或明确的占位 Def，避免在视觉资源未确定时绑定最终美术表现。
4. 让第一批事件结果可以推进叙事状态，同时保留已有随机事件的独立可用性。
5. 为叙事状态、奖励领取和存档加载补充聚焦测试或静态验证。

原版剧情已按修订稿接入，下一步优先做同一存档的游戏内回归。联动仍未实现，不在本轮范围内。

## 实现约束

新增地图事件通常需要同步：

1. `Defs/IncidentDefs/*.xml` 中的 `IncidentDef`。
2. `1.6/Source/` 中的 Worker，并加入 `MouseDisasterYear.csproj` 的显式编译项。
3. `MouseDisasterIncidentCatalog.cs` 中的目录项，否则设置页和调试菜单不会识别它。
4. `Languages/ChineseSimplified/` 中的事件文本和信件文本。
5. 如果使用访客控制，则同步检查 `MouseDisasterVisitorChoicePolicy`。
6. 如果需要广播触发，则加入或重构 `GameComponent_MouseDisasterBroadcastHope` 的事件池。
7. 如果有超时、多阶段或隐藏奖励，则使用可保存的 `GameComponent` / `MapComponent` 状态，不依赖只存在于运行期的静态字典。
8. 如果生成自定义世界地点，则优先复用已有世界对象机制；只有原版 `ItemStash`、`Outpost` 和 `BanditCamp` 不足时才新增 `SitePartDef` 或专用世界对象。
