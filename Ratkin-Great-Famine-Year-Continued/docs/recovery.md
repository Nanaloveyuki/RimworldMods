# 存档停用与卸载

## 操作

在已加载存档的 Mod 设置中，使用“当前存档与卸载准备”：

1. “仅对此存档停用新的鼠灾内容”将状态保存在该存档的 GameComponent 中，不修改全局事件开关或其他 Mod 设置。点击后请再保存一次当前存档，停用状态才会随存档持久化；已有事件参与者仍保留。
2. “备份并导出卸载用存档”暂停游戏并保存独立备份，然后清理序列化副本。原存档不覆盖，正在运行的世界不清理。
3. 成功后退出游戏，仅卸载本 Mod，保留鼠族等前置 Mod。重启并加载 `MouseDisaster-removed-*` 副本。
4. 确认副本可以加载、运行、保存和再次加载后，再决定是否删除旧档。`MouseDisaster-backup-*` 用于恢复，加载备份需要保留本 Mod。

导出失败时不要把备份当成已清理副本。设置界面与日志会显示原因。未知定义引用会中止导出，不猜测删除其所属数据。

## 清理边界

- 按当前 Mod 的 `ModContentPack.AllDefs`、程序集类型和当前/已知旧 PackageId 识别所有权，不删除其他 Mod 的特质、种族或基因。
- `MouseDisasterSettings` 属于全局 `ModSettings`，不写入游戏存档；清理器只移除存档中的鼠灾 GameComponent 和序列化引用，不修改全局 Mod 配置。
- 鼠灾 PawnKind 替换为仍加载的同种族 PawnKind，保留角色 ID。背景按同阶段、工作限制及技能增益选择原版近似背景。
- 隐藏派系替换为原版 Ancients 定义并保留派系 ID。穗音替换为兰迪；商人种类替换为原版大宗货物商人。
- 鼠灾特质、基因、健康状态、免疫记录、记忆、物品、区域、精神状态、作业、自定义 Lord 和信件移除。已有原版疾病、伤残和其他 Mod 的内容不回滚。
- 剧情地点使用原版无额外生成步骤的地点标记替换，保留地图父对象，避免已访问地点的地图失去父对象。
- 新增难民营地转为原版 `Site`，保留世界对象 ID、地图和居民；同名的地点部件单独转为原版标记，不混淆两种 Def。
- 鼠灾任务及其未生成的营地整体移除，清理任务、任务部件和待生成世界对象引用。观音土制作账单移除，同时取消引用它的当前作业、排队作业及预约。
- 鼠灾 GameComponent、MapComponent 和待处理事件数据移除。仍仅保存在鼠灾生成队列中的角色随队列取消。
- 清理交叉引用及作业预约时保持 Scribe 字典键值同步。未处理的鼠灾定义或已删除对象引用会阻止导出。
- 文件先写入临时路径，完整写入后才成为 `.rws` 副本。全局 Mod 配置不修改。

## 其他修复

- 乞讨双方分别使用游戏内半小时至两小时随机冷却；被打扰角色的冷却由全部乞讨者共享并随存档保存。婴儿不发起或接受乞讨，睡眠、倒地或无法说话的角色不作为目标。
- 广播无启用候选事件时不接受请求。条件不满足时按小时重试并提示，连续 72 次失败后取消并释放冷却。执行异常单独记录并取消，避免重复执行可能已有部分副作用的事件。不绕过玩家事件设置或原版触发条件，保留零冷却允许重复广播的设置。
- 世界生成期间不创建鼠灾隐藏派系、不进行其关系补丁修复，也不节流错误日志。运行时的关系扫描仅处理涉及隐藏派系的关系。生成后缺少玩家配置的可用派系时记录 `[MouseDisaster][FactionGeneration]`，不自动重建世界。

## 验证

### 从优化版迁移

- 支持基线：`local.mousedisaster.greatfamine`，`AL_MouseDisaster, Version=1.0.0.0`。退出游戏并备份存档，禁用优化版，仅启用 Continued，再直接加载旧存档；不需要先开新游戏，也不要先运行优化版的卸载清理器。
- 随附的 `AL_MouseDisaster.dll` 是纯保存类型转发程序集，将信件、组件、记录、枚举和任务驱动转到 `MouseDisaster.dll`，不包含第二套 Mod 入口、初始化器或 Harmony 补丁。不是优化版所有第三方二进制 API 的完全兼容层。
- 保留优化版额外的8个 Hediff 标记与 `MouseDisaster_MotherFeedBaby` JobDef。旧母亲喂食任务的目标 A/B 不一致，因此迁移时结束该未完成任务，由现有 AI 重新选择；不消耗或生成食物，不移植这套自动喂食行为。
- 不分发 `MouseDisasterPerfPatch.dll`：其缓存节流由本项目现有实现承担，原补丁还包含未跨存档重置的静态时间记录和静默异常处理。
- 原版或优化版与 Continued 同时启用时，`LoadFolders.xml` 停止加载 Continued 内容并提示重启，避免两套同名类型和补丁竞争。
- 验证命令：`pwsh -NoProfile -File scripts/verify-optimized-compat.ps1`。自动测试覆盖真实 DLL 类型解析和旧 Def 覆盖，但仍需优化版真实存档的冷启动加载、运行、另存和重载验收。

使用 PowerShell 7：

```powershell
./scripts/verify-recovery.ps1
./scripts/verify-event-recovery.ps1
./scripts/verify-refactor.ps1
./scripts/verify-pawn-components.ps1
./scripts/verify-narrative.ps1
```

`verify-recovery.ps1 -SavePaths <路径>` 仅在内存中测试，不写入存档。该模式用占位定义验证结构、角色 ID 保留及重复清理的一致性，实际替代定义由游戏运行时解析。

测试不代替真实卸载后的加载、运行、保存、再加载。大地图派系异常尚无可复现样本；目前是范围收紧与诊断，不能视为该反馈已完全解决。
