# 游戏内原生呈现、显式页面能力与统一动效

IrisMenus 的双主题网页原型已用于验证布局与交互，但现有游戏页面是消费者提供的绘制回调，不是可自动分析的控件树。完整新宿主准备沿用游戏端 C#／IMGUI 与现有页面、搜索、保存所有权，在同一页面身份上增加可选呈现描述，不嵌入网页，也不建立平行注册体系。

用户已认可原生组件总体，要求先修正点击后的黄色 outline 和 Endfield 矩形直角风格，再准备完整新宿主。认可组件不等于接受本文所有产品建议。本文仍为 `proposed`：区分已明确要求、必须保持的现有契约和待确认策略，不表示新宿主已实现、公开接口已定稿或游戏已验收。源码依据、入口几何与状态转换见[筹备报告](../references/ui-redesign-preparation.md)。

## 当前实施范围

`Source/UI/` 已有独立的原生可复用组件及其局部动效，公开类型使用 `IrisMenus.UI` 命名空间；现有开发模式入口为 **IrisMenus > Native UI components**，展示值不写入 Mod 设置。组件接口和输入／资源规则见[原生组件参考](../references/native-ui-components.md)。

本轮只修组件并维护完整实现准备，不迁移主 `MenuWindow`，不添加打不开新版宿主的空入口。点击黄框的修正应区分指针点击与键盘导航焦点，保留可辨识的键盘焦点反馈；矩形表面采用直角，不把 radio、slider thumb 等本来就是圆形的语义图元一并方化。当前实际游戏宿主仍为旧版，游戏运行验收与既有构建证据分别以组件参考和后续实际记录为准。

## 已确定的视觉输入

- 网页原型采用顶栏搜索、左侧 Mod 导航、页面 tabs、正文、章节目录／说明和底栏；窄窗口将辅助导航收进抽屉。
- Light 底栏使用近黑色填充与浅色内容；Sidebar 不展示 Mod 总数或页数。数字不再承担装饰用途。
- Dark 与 Light 共享信息结构，不通过主题切换重置设置、搜索或当前页面。
- 这些是游戏实现的视觉依据，不把网页像素断点、示例 Mod 数据或会话状态直接当成游戏契约。

### 旧宿主中的新版入口位置

入口位置以用户提供的 1280×750 截图为准：放在“显示底部 IrisMenus 按钮”正下方，与“记住上次页面”同行；不是在底栏下面再加一行。普通 inline 布局复用 `layout.MainButton.x/width`，入口 Rect 为 `(layout.MainButton.x, remember.center.y - 12f, layout.MainButton.width, 24f)`。普通 `remember` 高 22，因此入口比它的 y 小 1，二者中心相同；不使用截图屏幕坐标硬编码。

`MenuLayout.Calculate` 的底栏高度保持 **72／120／152** UI 单位不变。非 inline 和 compact 分支已有 44 高的 `layout.MainButton`，改为上 20 高的 checkbox 和下 24 高的入口，x／width 不变，命中区不重叠；checkbox 标签保持单行，过长截断并以 tooltip 提供全文。这是窄版的明确例外：`remember` 与滑条位于更上方，不能再强行把入口移到它的 y。详见[入口几何](../references/ui-redesign-preparation.md#旧宿主入口的精确几何)。

保留 `MenuRegistry.Open()`、原版设置路由及游戏底部按钮的旧版默认行为。只有完整新版呈现确实可打开后才一并接入此入口；本轮不显示占位、无操作或“稍后开放”按钮，也不把组件展厅当作新宿主。

## 建议决策

### 1. 保留页面与保存模型，替换宿主呈现

继续使用 `MenuRegistry` 的 page ID、`MenuSession` 的选择与保存门控、`MenuCatalog` 的元数据索引，以及 `MenuBrowseState` 的查询／结果／目标状态。Mod rail 按现有 `Content` 关系合组，tabs 展示真实注册页面；SubItem 仍是页面分类，不变成页内章节。`ActionLauncher` 保留 owner action 入口语义，不伪装成空设置 tab；原版 adapter 管理及 owner action 的可见、可用、确认与失败反馈都在完整宿主范围内。

建议保留 `MenuWindow` 为唯一 Window 和生命周期所有者，让旧版与新版成为它内部的两种呈现实现，共用唯一 `MenuSession`、`MenuBrowseState`、有效页面集合和 catalog。切换呈现不新建第二个 session、不堆叠两个宿主、不复制设置值；同页切换不额外保存或伪装为关闭。新模式的全屏布局按游戏 UI 单位、长翻译和 UI scale 计算，旧模式窗口几何保持原含义。若实施时选择不同的窗口组织，也必须满足相同的单一所有权及无重复保存约束。

消费者继续持有设置值和 `MenuPage.Save`；默认保存委托来自 `owner.WriteSettings`。正常切页先 `MenuSession.Select`，成功后才提交 rail／tab 选中与 browse 状态，失败保持原页、值、查询、滚动与输入层。正常关闭先保存当前页，再保存宿主设置，任一步失败均保持窗口；关闭不是取消，不引入统一提交、回滚或逐帧保存。动态注册 Rebind 不调用离页保存，且不为淡出保留已删除页面 drawer。

新旧呈现共用同一页面身份，不各存一份“当前页面”。语言或 `MenuRegistry.Revision` 变化时释放旧 catalog，重建元数据并按 `ResolveReplacement` 重新绑定；同 ID 保留 Listing 滚动，失效页面的章节、焦点和动画状态及时释放。记忆继续服从 `RememberState`、`LastPage`、`LastSubItems` 与 `HostView`；新增主题与减少动态效果需要真实读写，新增抽屉／说明默认只为窗口会话状态，尚未决定跨重启策略。

### 2. 新呈现能力显式声明，旧 drawer 保持完整

在既有页面上附加可选描述，包含稳定章节 ID、本地化标题、说明内容、定位目标及主题支持声明。目录、搜索定位和折叠状态共用同一 page／section／anchor 身份；不扫描绘制过程、反射私有字段或按显示标题建立身份。

没有描述的页面仍执行原绘制回调，不生成假的章节、说明或字段。`RegisterListing` 已封装 `MenuScrollView`，`MenuSectionView` 自持滚动，原版 adapter 直接转发自己的 drawer；新版内容区只提供裁切后的 viewport，不再统一套第二层滚动。新的原生页面也必须明确唯一滚动所有者，目录与搜索定位委托同一所有者。

建议 Light 宿主中的未知 drawer 使用明确的深色兼容内容区，并在调用范围内还原合适的 GUI 状态；不能只画深色背景却把浅色文字令牌泄漏给 legacy drawer。只有显式声明主题支持的页面才使用 Light 内容呈现。是否采用这一产品策略仍待确认；在确认前不能承诺所有第三方设置页完整浅色化。

### 3. 内部主题与动效由宿主集中管理

新增内部呈现模块，向宿主绘制提供同一帧的主题、动画值、几何、绘制裁切和输入所有权。它隐藏 IMGUI 的多 pass 与平台差异，不把帧时间、插值和 overlay 事件规则散落到消费者。

- 使用真实时间，每帧固定采样；Layout、鼠标事件、Repaint 不重复累加 delta。
- 状态键使用稳定语义身份，不使用标题、列表位置、Rect hash 或当帧 control ID。
- 转场可打断、可反向，从当前显示值重新定向；已删除页面不为淡出继续执行旧 drawer。
- 内容层、抽屉、select／确认框明确输入层级；Esc 只处理最上层。动画中的绘制、命中和裁切共用几何；拖动控件保持稳定身份。
- legacy drawer 不做新旧两页实时 crossfade，也不因动画额外执行一次回调。优先使用不改变交互几何的视觉反馈；需要位置动画的原生控件单独验证拖动与点击。
- 减少动态效果持久化，启用即将当前转场推进到目标，不延迟关闭或强制平滑定位。

动效目标包括窗口开关、导航选中态、tabs、说明展开、抽屉、宿主原生控件反馈和搜索定位；不承诺接管第三方页面内部动画。先静态后动效是实现与验收顺序，不是把完整动效从交付范围删掉。

### 4. 关闭动画服从持久化与资源生命周期

正常关闭依次经历保存门控、Closing、最终移除。保存失败不进入 Closing；Closing 期间不接受内容编辑，继续遮挡输入并持有暂停与 Frost 资源；完成后走正常移除路径，不重复保存或播放关闭音效。

`PreClose` 只承担最终释放与既有兜底，不负责启动可见动画。返回主菜单、窗口栈替换等强制清理不能被退出动画阻止；强制清理与交互关闭必须区分。

### 5. Frost 复用现有后端，不成为第二套页面渲染器

保留 1.6／1.7 各自的背景采样和资源生命周期，普通底色与 shader `_Fill` 使用同一主题令牌；退出 alpha 同时覆盖普通填充与材质绘制。

Frost 不提供页面截图，不等同于包含所有窗口的 backdrop blur，不用于旧 drawer 截图转场。不为每个抽屉重复抓取场景、创建材质或编译 shader，也不要求两版算法像素一致。

### 6. 不把网页示例能力无条件推广到所有 Mod

搜索继续使用 `MenuCatalog` 的分批元数据索引，不执行未选页面 drawer。点结果必须先通过 `session.Select(hit.Page)`，再进入目标页、保留结果查询／范围／分页／滚动，并调用有效的 `Focus(anchor)`；返回结果先保存目标页，失败留在目标页。新增章节定位先展开、等待有效布局，再交给唯一滚动所有者定位与高亮，不建立第二套锚点坐标表。无 focus 的命中只打开页面，不伪造精确定位。

`MenuBrowseState.Search` 现有行为是修改查询后退出 target 模式并重置分页，不额外保存；`Navigate` 则清查询并切换 owner 范围。新版不得把这两类动作混为一次普通切页，也不暗中改变保存时机。目录／说明／抽屉切换不产生新的页面身份；顶层 overlay 消费 Esc 后，底层不能再收到同一事件。

内联编辑、通用修改计数和恢复默认需要消费者声明字段类型、Get／Set、可见／可用条件、默认值或 Reset、脏状态与保存归属；本 ADR 不擅自新增该接口。缺少声明时不显示误导性的计数、重置或“已保存”提示。IrisMenus 自身可使用已知设置实现真实操作，但 density、scale、提示延迟等原型选项只有实现真实游戏行为后才进入设置页。

## 取舍

|方案|取舍|
|---|---|
|保留 C#／IMGUI 并扩展显式描述（推荐）|复用真实注册、保存和渲染链；需要自行实现原生主题控件与动效，但兼容责任明确|
|游戏内嵌入网页／迁移全部消费者|能复用网页表现，却新增运行时、输入、字体与游戏状态桥接；现有 drawer 无法直接迁入|
|执行或反射 drawer 自动识别控件|短期减少注册工作，长期依赖绘制副作用和私有实现；无法可靠获知默认值、滚动、裁切或保存语义|
|只改颜色并分散添加 tween|改动小，但不能解决多 pass、输入穿透、拖动身份与关闭保存门控|

## 实施门槛与验证

按下列顺序推进，每道门都要有实际游戏证据；不以网页截图或引擎替身测试替代游戏验收。

1. **静态宿主：** 单一 Window／session 所有权、真实注册与 tabs、原版托管管理、owner actions、导航搜索、语义主题、Light 近黑底栏、无 Sidebar 计数、IrisMenus 自身真实设置页、legacy 隔离和单层滚动；无动画时所有既有页面与保存路径可用。
2. **动效底座：** 复用原生组件的每帧快照、稳定身份、可打断转场、输入裁切和拖动规则；补齐宿主减少动态效果持久化与保存门控关闭，覆盖保存失败、嵌套 Esc 和连续操作。
3. **页面描述与完整交互：** 在既有 page ID 上提供可选章节／说明，目录与窄窗口抽屉共用定位，接入完整宿主动效；Listing 全量回调不得称为虚拟化。
4. **入口与交付：** 新版真正可打开后，按固定几何接入旧宿主底栏入口，旧默认入口不变；完成地图／世界／主菜单、长翻译与 UI scale、动态注册、自滚动与特殊 adapter、重开／重启记忆、Frost 失败回退，并更新真实消费示例和接入文档。

|事项|建议默认|影响|
|---|---|---|
|版本产物|先交付并验收 1.7；保留现有 1.6 产物|同时更新 1.6 需要独立构建、背景渲染和输入验收，不能由源码共用推定通过|
|legacy 浅色策略|Light 宿主＋深色兼容内容区|若要求所有页完全浅色，必须安排消费者显式迁移，宿主不能单方面保证|
|搜索编辑与计数／重置|先保持导航搜索；通用能力另立字段契约决策|不是删掉已确认目标；当前尚未决定是否把这些网页示例纳入游戏交付|
|“当前 Mod”范围|沿用当前 OwnerId 语义，先不改持久化键|若指整个内容包，需要处理同包多个 Mod 类型并显式迁移搜索范围|
|状态记忆|保留现有宿主和 Listing 记忆范围；新增抽屉／说明暂为窗口会话状态|若要求全部跨重启保存，需要定义稳定键、清理和与 RememberState 的关系|
|未来默认入口|本轮及下一步保留旧默认入口，仅增加显式新版入口|是否最终默认打开新版另行决定，不增加自动迁移或无功能宿主偏好开关|

待定行不覆盖用户已明确的组件修正、旧版默认入口保留与入口位置。其余产品建议继续保持 `proposed`；本轮准备不等于完整宿主交付或游戏验收。
