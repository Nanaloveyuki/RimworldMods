# ADR 0001：先修账务与工种兼容性，再缩减运行期开销

本 fork 先恢复收费、工作归属与成功结算的一致性，再优化扫描和补丁。bug 以 GitHub issue 为事实与验收入口；本 ADR 记录实施次序及不能被优化改变的约束，后续取舍变化时更新或用新 ADR 替代，不追加流水账。

版本目标与验收环境已由 [ADR 0003：迁移到 1.7，冻结 1.6 发布内容](0003-rimworld-1-7-migration.md) 调整：先迁移并在真实 1.7 验收正确性，再做性能；不再等待 1.6 运行环境。本文其余经济语义和性能顺序继续适用。

## 范围与证据

- 基线为 vendor commit `8539fff`，上游 PPTE2 v2.3.2 / `5e5bab4db0b5cd4a55f161197a0a0caa085df08d`，保留 MIT 与既有 1.6 发布。初期沿用包名，2.5.0 包名切换见 ADR 0003。最初按 1.6 制定本 ADR；后续迁移到 1.7 的范围与旧版保全要求由 ADR 0003 规定，关闭 issue 和进入性能批次以 1.7 正确性验收为门禁。
- 用户报告的 NewRatkinPlus 人力发电漏管是已知现象。旧 1.6 Released 源码为历史依据；现已在真实 1.7 观察两条派工、完整/中断会话、即时余额、设置与存读档，运行证据见 [README](../../README.md#17-验收与支持范围)。用户随后确认 Prison Labor 在个人生存档运行良好；性能批次不调整其兼容对接，也不将此实测混作自动化接管验收。
- 前次零囚犯探针运行原 manager/social 调度方法、工资和赎身代码、原版集合 getter，游戏对象边界为计数替身。两图各 500 个非囚犯 pawn、60,000 tick，默认设置触发 14,008 次容器递归入口、500,000 次 hediff 查询；它证明控制流次数，不是游戏 profiler 耗时，也不覆盖所有 Harmony、Need、UI 调用。临时探针已删除。
- 术语采用 [词表](../../GLOSSARY.md)：工种可见、派工许可、工作归属、计件单位是四项独立能力。

## 决定与实施门禁

### A. 正确性批次：先关闭账务与兼容性缺口

实施顺序为 **#5 → #6 → #7 → #8**。每项单独回归；允许复用前项已稳定的工作快照，不把性能调度重写混入 bug 提交。

| Issue | 缺陷与改动约束 | 必须证明的行为 |
| --- | --- | --- |
| [#5 免费食物误拒绝](https://github.com/Nanaloveyuki/RimworldMods/issues/5) | 找食与进食共用收费豁免规则；保留实际进食安全网 | 全局免费、指定食物免费、个体免费均能正常找食；个体强制收费仍覆盖全局免费；实际份数与赊账行为保持 |
| [#6 通用计件归池漏薪](https://github.com/Nanaloveyuki/RimworldMods/issues/6) | prefix 按值保存 pawn、工种及必要结算能力，不在 postfix 重新读取已归池 Job/Driver；用值类型状态 | 成功工作在归池/不归池/池满路径各付一次；失败、中断不付；专用单位不双付；连续任务不串工种 |
| [#7 失败搬运计薪](https://github.com/Nanaloveyuki/RimworldMods/issues/7) | 先检查真实放置结果，再按 Direct、Hauling、身份与模式结算 | 失败不付，重试成功仅付一次；Near 和非搬运不付 |
| [#8 第三方 WorkType 漏管](https://github.com/Nanaloveyuki/RimworldMods/issues/8) | 按 [ADR 0002](0002-work-attribution-and-direct-jobs.md) 分离工种发现、派工与结算识别，覆盖仓鼠轮独立囚犯派工 | 配置可发现且持久化；普通工作来源、独立 JobGiver 来源均识别正确；未知任务不猜测归属；持续发电不伪造产出单位 |

修复期先在能覆盖真实缺陷的 seam 保留确定性回归：池化必须经过真实清理/清空顺序，搬运必须覆盖 false→重试→true，找食必须覆盖优先级组合。单纯 mock 转发、源码文本断言或“没抛异常”不算验收。

A 批次结束须按 ADR 0003 在真实 1.7 环境观察受影响路径，包括 NewRatkinPlus 囚犯发电、即时余额、身份变化、存读档，以及可用的 1.7 软依赖适配。不能直接在 1.7 加载 vendor 的旧 1.6 DLL 充当迁移；必须使用已适配的 1.7 构建。旧 1.6 运行验收不再是前置条件，旧发布只做内容保全；1.7 行为未验收时不关闭 issue 或进入性能批次。

### B. 性能批次：先省重复工作，不先改经济时间语义

只有 A 的验收完成后，才在其结果上建立性能基线。优化顺序如下；每步需要同场景前后对照，不以静态推断宣称 TPS 提升。

1. **去掉高频全量发现。** 工资、社交等只作用于 spawned pawn 的路径使用原版已维护的 spawned 囚犯集合；同次调度复用候选。容器内/未生成囚犯、旧存档初始化与服刑状态单独处理，禁止把所有 `PrisonersOfColony` 机械替换。
2. **拆活跃处理与遗留清理。** 新社交行为全关时不扫描候选；健康状态改为身份事件维护、读档重建与低频兜底。没有候选不等于没有借款、战斗、娱乐尾款、健康状态或旧会话；先清完相应遗留再休眠。
3. **局部消除分配与重复查询。** 节拍判断先于 manager 查找；非目标 pawn/RecordDef 尽早退出；收费确认后才创建进食状态；单次支付复用父母集合、账户与 manager。越狱判断采用已确认等价的直接 Lord 获取。不要缓存整轮社交余额：乞讨、借款会改变后续抢劫条件。
4. **降低每候选附加成本。** 缓存每地图劳作区引用并处理地图/读档生命周期。保留 postfix 行为作为第一步；若 profiler 证明被禁区域的账单配料搜索是热点，再单独评审前置否决及 Harmony 副作用，不能直接改 prefix。
5. **依据实测再做索引或采样调整。** 借款按借款人索引、单次结算的 pawn ID 索引、监督者集合复用可候选。改变研究贡献采样为真实研究事件会改变份额口径，需独立决定，不能作为无语义变化优化混入。

以下行为不因性能优化改变：即时可消费余额、自动还债顺序、工资动机反馈、个体设置优先级、已保存的工种选择、专用/通用计件互斥，以及捕获/释放/招募/死亡/离图/换图/读档的状态收尾。

本轮 `2.4.1` 实施 B1–B4 的等价路径：普通工资/赎身优先复用 spawned 集合；地图存在已跟踪的未生成囚犯时才回到原完整集合，保持容器工作与申请行为。社交发起者用 spawned 集合，目标集合延迟到真实行为需要目标时发现并在本地图本轮复用；仍包含原有容器目标，余额不跨行为缓存。身份事件维护健康状态，120 tick 清理已跟踪遗留，2500 tick 完整兜底和旧档重建；不再每 120 tick 扫全部殖民者。父母代付复用单次账户/权重快照，劳作区缓存以 AreaManager 弱键隔离生命周期。工资、研究、社交、赎身节拍和 Prison Labor 对接不变。

性能证据限于真实游戏中直接调用 manager 的受控调度段，不是整局 TPS：每图 100 名自由殖民者，0/1/20/100 名囚犯，单图/双图，60000 tick 窗口；关闭详细日志，预热同长度窗口后测三次。原版集合 getter 上仅计数补丁，计时与线程分配包含计数成本，前后口径相同。对照及回执见 [README 性能重写](../../README.md#241-性能重写)。索引、监督者缓存和改变研究采样不在本轮。


### C. 零囚犯不是全局关机

- 活跃处理只在相关候选存在时运行；判空不得调用会重建全列表的 `PrisonersOfColony.Count`，更不得在每个 Harmony 热入口扫描所有地图。
- 清理队列/集合非空时继续收尾；初次读档至少重建一次必要索引，不能依赖本局捕获事件是否发生。
- **无囚犯时仍执行劳作区对自由工人的禁工，以及“仅囚犯”账单拒绝非囚犯。** 二者是玩家配置，不是当前囚犯数量的衍生结果；存档字段也照常读写。
- 游戏、地图、pawn 和 job 状态不得放进没有失效规则的跨存档静态缓存。优先复用原版维护集合和单次操作上下文，不新建万能注册框架。

## 验收矩阵

| 场景 | 正确性观察 | 性能观察 |
| --- | --- | --- |
| 从未有囚犯、且没有遗留状态 | 殖民者正常吃饭；已画劳作区与仅囚犯账单继续限制 | 例行活跃处理不做全 pawn/容器发现；非目标进食不分配收费事件 |
| 最后一名囚犯释放、招募、死亡、离图或装入容器 | 账户/思想/健康/服刑/娱乐/战斗按原有规则收尾，容器状态不被当成无囚犯丢弃 | 清理完成后进入对应休眠；捕获、spawn、地图加入或读档可恢复 |
| 1 / 20 / 100 名囚犯；单图与多图 | 时薪、专用计件、通用计件、债务和儿童代付结果符合 A 的基线 | 分别记录扫描次数、分配字节、采样段耗时；不得只看整局 TPS |
| NewRatkinPlus 发电两条来源 | 工种配置、归属与结算满足 ADR 0002；中断与存读档不双付 | 不新增每 tick 全 Def/WorkGiver/建筑发现 |
| 高频清洁、播种、搬运、复杂账单 | 一单位成功一次工资，失败不付；禁工不被优化放行 | 分开统计完成事件与寻工候选，避免把候选成本误报成每工作完成成本 |
| 内置劳工开关切换、Prison Labor 接管 | 派工权与工资来源保持各自语义，不越权启用禁用工种 | 已关闭功能只保留必要收尾，不进行新行为扫描 |

## 不选的方案与待调查项

- 不先放大轮询间隔、不改为每小时批量发薪：会改变短时工作、消费、还债与研究份额，不是等价优化。
- 不以显示名、任意 JobDef 猜测工种，不把全部第三方工种默认开放给囚犯；保留原禁止工种策略。
- 不在每个 bug 中引入独立兼容判断，也不预建支持所有 mod 的通用插件框架。
- `BillWorkerModeUtility` 静态强引用生命周期、娱乐结束与外层 joy tick 顺序、ThinkTree 插入优先级、劳工允许列表固定高度及研究贡献口径仍是独立调查候选；尚未完成行为证据的项不冒充已修复 bug，不借性能批次静默改语义。确认可见缺陷后先建 issue，再纳入 A 的验收门禁。
